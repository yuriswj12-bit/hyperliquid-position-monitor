# Hyperdress.AI

**项目名称**：Hyperdress.AI  
**赛道方向**：DeFi / On-chain Analytics / AI × Crypto  
**项目类型**：个人工具 + AI Agent

---

## 1. 问题陈述（Problem）

在 Hyperliquid 上，很多交易者（尤其是做空者）会进行大额建仓或突然平仓，这些行为往往蕴含重要的市场信号。

然而目前存在以下痛点：
- 没有简单工具能**持续监控特定地址**的仓位变化
- 异动发生时无法及时收到通知
- 想分析某个地址的历史行为或统计数据，需要手动查很多地方，效率低
- 普通用户难以快速从海量链上数据中提取有价值的信息

**核心问题**：缺乏一个**简单、实时、能对话式查询**的 Hyperliquid 地址监控与分析工具。

---

## 2. 解决方案（Solution）

**Hyperdress.AI** 是一个结合**后台监控 + AI 聊天分析**的工具。

**核心思路**：
- 用户配置需要监控的地址（尤其是空头地址）
- 后台持续监控这些地址的仓位变化
- 出现重要异动时通过 **Telegram** 自动推送告警
- 用户可以通过本地聊天框，用自然语言向 AI 提问，快速获取统计数据和洞察

---

## 3. MVP 核心功能

| 功能               | 描述                                      | 优先级 |
|--------------------|-------------------------------------------|--------|
| 后台地址监控       | 持续监控配置地址的仓位变化                | 高     |
| Telegram 告警      | 平仓、大额新建、显著加减仓、协同建仓时推送 | 高     |
| AI 聊天分析        | 支持统计类问题、查询当前持仓、历史交易    | 高     |
| 本地极简网页       | 以聊天框为主要交互界面                    | 高     |
| Docker 部署        | 支持长期后台运行                          | 高     |

**聊天框 MVP 重点支持**：
- 统计类问题（过去XX时间新建/平仓数量、平均成本等）
- 查询地址当前持仓
- 查询地址历史交易记录

---

## 4. UI / UX 设计

**极简设计理念**：
- 主界面只有一个聊天框（参考 Grok 风格）
- 左上角显示产品名 + 监控状态（监控中：XX 个地址）
- 右上角无复杂菜单，所有交互通过聊天完成

**目标**：让用户感觉像在和一个懂 Hyperliquid 的 AI 助手聊天，而不是操作一个复杂工具。

---

## 5. 技术架构

- **数据来源**：Hyperliquid 官方 WebSocket + REST API
- **后端**：Python + asyncio
- **数据存储**：本地 SQLite
- **AI 能力**：Grok API（自然语言理解 + 数据分析）
- **告警**：Telegram Bot API
- **前端**：FastAPI + HTMX（极简聊天界面）
- **部署**：Docker Compose

---

## 6. 创新点 / 差异化

- **监控 + 分析一体化**：不仅能收到告警，还能立刻用聊天追问更多细节
- **极简交互**：用聊天框完成大部分操作，降低使用门槛
- **本地优先**：数据存储在本地，隐私性更好
- **专注空头地址监控**：针对性更强

---

## 7. MVP 成功标准

- 能稳定后台监控地址并通过 Telegram 推送异动
- 聊天框能较好回答统计类问题和基础查询
- 支持 Docker 一键部署并长期运行
- 用户能通过简单对话完成日常分析需求

---
